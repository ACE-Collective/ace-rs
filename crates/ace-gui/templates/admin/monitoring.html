In the log

A check's records are also log lines, under the target ace_monitor. And when a root's analysis pass completes, ACE logs one metrics event for the root under the target ace_metrics, the message METRICS (root): and the event as JSON on one line, and then one for each module that ran in the pass, the message METRICS (module): and its JSON. All are INFO, so ACE4_LOG must allow them.

A task's run is one claim of it: from when its lease was taken to when its end or its delay reached the core. That is the module's work with what surrounds it, the task process's start, its file's download and its result's upload, but not the time the task waited for a pool or a delay. A delayed task's runs add up.

Field of the root's eventWhat it is
event_typeroot
timestampWhen the pass completed, in UTC.
root_uuidThe root.
passWhich of the root's passes completed, from 1.
total_analysis_time_secondsThe run times of the root's tasks in the pass, added up, the core's hooks included.
pass_open_secondsHow long the pass was open, from the first work queued on the idle root to its last task's end. It includes the time tasks waited for a pool or for a delay to end, and tasks run side by side, so it isn't the time analysis took.
alert_typeThe root's alert type, or null when its submitter named none.
is_alertWhether the root is an alert.
queueThe root's queue.
observable_countThe root's observables.
observable_type_countsThe same, by observable type.
task_countThe root's module tasks, from every pass: the ones queued to run, which each ran or was cancelled first.
failed_task_countThose that failed.
outcomecancelled when the root's analysis was cancelled, completed otherwise.
Field of a module's eventWhat it is
event_typemodule
timestampThe root's event's, which joins them.
root_uuidThe root.
passThe pass, as in the root's event.
moduleThe module.
analysis_time_secondsThe run times of the module's tasks in the pass, added up.
percentageThat as a share of the root's total_analysis_time_seconds.
exec_countThe module's runs in the pass.
cache_hit_countFor a module whose results the analysis cache keeps, when it looked any up in the pass: the results it took from the cache, each in place of a task.
cache_miss_countThe lookups that found none, after which a task was queued.
cache_write_count_insertThe module's results the pass kept for later alerts.
cache_write_bytes_compressed_sumTheir sizes, compressed, in bytes.
cache_lookup_ms_sumHow long the lookups took, hits and misses, in milliseconds.
cache_lookup_ms_maxThe longest of them.
