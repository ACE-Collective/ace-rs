# Differences between ace3's and ace4's trees

`ace compare` (`crates/ace-app/src/compare.rs`) diffs ace4's normal form of each sample with ace3's in `reference/`, and classes each difference by the first row here that matches it. `tests/e2e/run` enforces the acceptance threshold (`docs/acceptance.md`): it fails on a difference no row matches, in any sample, and on a row that matches nothing. A row needs a reason someone verified, by reading both systems' code and looking at the values. In the Samples column, `*` matches any text in a sample's path. In the Path column, a `*` segment matches one segment of the JSON pointer, `**` any number, and a `*` inside a segment any text. The When column narrows a row: `ace4 only` is what ace3 doesn't have, and `ace3 holds <text>` a value of ace3's with that text in it.

A row covering only samples under `local/` has to name them, because those samples are git-ignored and CI doesn't have them.

ace3's trees ran at the commit in `reference/index.json`, which is newer than the commit the five modules were ported from (`tools/ace3/dumps/reference/index.json`). A row marked *drift* is something ace3 added after the port. The trees follow the newest ace3 (`PLAN.md` decision 14), so rerun `make-trees` after ace3 moves, then port or list whatever changed.

A module ace3's trees ran and ace4 doesn't have isn't listed: the command takes its results out of both forms and counts them. When a module is ported its results start being compared, and what it added outside its results moves out of *Effects of modules not ported*.
